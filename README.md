# نظام إدارة المطاعم (RMS)

نظام إلكتروني متكامل لإدارة المطعم، مبني بنفس فكرة وبنية نظامَي **إدارة المدارس (SMS)** و**إدارة المستشفيات (HIS)**:
هرم تنظيمي واضح، صلاحيات حسب الدور (RBAC)، سجل تدقيق لكل عملية حساسة، وواجهة عربية RTL.

يتكوّن من ثلاثة أنظمة تعمل على قاعدة بيانات واحدة:

| النظام | الوصف | من يستخدمه |
|---|---|---|
| **إدارة المطعم** | لوحة تحكم، تقارير المبيعات، مخزون بوصفات تُخصم تلقائيًا، موظفون، سجل تدقيق، إعدادات الضريبة/الخدمة | المالك، المدير |
| **نظام المنيو** | تصنيفات وأصناف وإضافات وصور، "نفد/متوفر"، **منيو عام للزبون عبر QR** على كل طاولة | المدير (إدارة) + الزبون (عرض وطلب) |
| **نظام الكابتن** | خريطة الطاولات بالألوان، أخذ الطلب، إرسال للمطبخ، الموافقة على طلبات الزبائن، الفاتورة، نقل الطاولة؛ + **شاشة المطبخ (KDS)** + **الكاشير** | الكابتن، المطبخ، الكاشير |

## المقابلة مع نظامَي المدارس والمستشفيات

| SMS (مدارس) | HIS (مستشفى) | RMS (مطعم) |
|---|---|---|
| مديرية التربية | — | **المالك** (يرى كل الفروع) |
| المدرسة | المستشفى | **المطعم/الفرع** |
| الصف ← الشعبة | القسم ← السرير | **القاعة ← الطاولة** |
| الطالب | المريض | **الطلب (Order)** |
| المواد/المنهج | الخدمات الطبية | **المنيو (تصنيف ← صنف)** |
| الحضور والغياب | المواعيد | **حالة الطاولة والطلب** |
| الأقساط والمحاسبة | الفوترة والتأمين | **الفواتير والدفع (نقد/بطاقة/مقسّم)** |
| الصيدلية/المخزون | المخزون | **المخزون + الوصفات** |
| مدير/معاون/مدرّس/ولي أمر | مدير/استقبال/طبيب/ممرض | **مالك/مدير/كاشير/كابتن/مطبخ** |
| رمز QR للطالب | — | **رمز QR لكل طاولة** |
| سجل التدقيق | سجل التدقيق | **سجل التدقيق** |

## دورة الطلب

```
الزبون يمسح QR ──► أصناف "بانتظار الموافقة" ──► الكابتن يوافق ──┐
الكابتن يفتح الطاولة ويختار الأصناف ─────────────────────────────┤
                                                                  ▼
                    المطبخ/البار/الحلويات (حسب محطة التصنيف): انتظار ► تحضير ► جاهز
                                                                  ▼
                              الكابتن يقدّم ► يطلب الفاتورة ► الكاشير يدفع
                                                                  ▼
                       الطاولة "تنظيف" ► فارغة · خصم المخزون · تقارير · تدقيق
```

## الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| `owner` | كل شيء على كل الفروع |
| `manager` | كل شيء في فرعه: منيو، طاولات، مخزون، تقارير، موظفون (عدا المدراء)، إلغاء الطلبات |
| `cashier` | الفواتير والدفع والخصم، التقارير، رؤية الطلبات |
| `captain` | الطاولات، أخذ الطلبات، الموافقة على طلبات QR، طلب الفاتورة، التقديم |
| `kitchen` | شاشة المطبخ فقط (لا يصل لسجل الطلبات ولا الفواتير ولا التقارير) |

قواعد أمان وتشغيل مطبّقة على الخادم (وليس في الواجهة فقط):
- الأسعار تُقرأ دائمًا من المنيو في قاعدة البيانات — لا يُوثَق بسعر مرسل من العميل.
- لقطة (snapshot) للاسم والسعر في كل صنف طلب، فلا يتغير الطلب القديم بتعديل المنيو.
- طلب واحد مفتوح لكل طاولة (قفل على مستوى الصف داخل معاملة) — لا طلبات مكررة عند ضغط كابتنين معًا.
- أصناف الزبون (QR) لا تُحسب ولا تصل المطبخ قبل موافقة الكابتن؛ والمسارات العامة محدودة المعدل.
- إلغاء صنف مُرسل يتطلب سببًا؛ وبعد بدء التحضير يتطلب مديرًا. الخصم للكاشير/المدير فقط.
- الدفع يقبل دفعات متعددة ويجب أن يغطي الإجمالي؛ لا دفع مزدوج.
- كلمات المرور الضعيفة/المؤقتة تُجبر على التغيير قبل أي استخدام للنظام.

## التقنيات

- **Backend**: Node.js + Express + Sequelize + PostgreSQL + JWT
- **Frontend**: React + Vite + React Router — واجهة عربية RTL بتصميم زجاجي بروح macOS: شريط قوائم علوي بساعة حيّة، Dock بتكبير الأيقونات وقفزة الفتح، نوافذ بأزرار الإشارات الثلاثة (رجوع / إخفاء الشريط الجانبي / ملء الشاشة)، شاشة دخول كشاشة القفل مع اهتزاز عند الخطأ، لمعة زجاج تتبع المؤشر، حركات نابضية وعدّادات متحركة، ووضع فاتح/داكن/تلقائي. تحترم إعدادات تقليل الحركة والشفافية، والطباعة بلا تأثيرات.
- التحديث الحي للمطبخ والكابتن بالاستعلام الدوري كل 4–5 ثوانٍ (بدون WebSocket لتبسيط النشر)

## التشغيل محليًا

المتطلبات: Node.js 18+ و PostgreSQL 14+.

```bash
# 1) الخلفية
cd backend
cp .env.example .env     # عدّل بيانات قاعدة البيانات (أنشئ قاعدة restaurant_rms)
npm install
npm run seed             # ⚠️ يعيد إنشاء الجداول ويعبّئ مطعمًا تجريبيًا
npm run dev              # http://localhost:4000

# 2) الواجهة (نافذة أخرى)
cd frontend
npm install
npm run dev              # http://localhost:5173
```

أو بأمر واحد: `docker compose up --build` ثم افتح http://localhost:5173 (ثم `docker compose exec backend npm run seed` لأول مرة).

## تطبيق الكابتن (Android)

تطبيق أصلي بـ Kotlin + Jetpack Compose في مجلد `android/` بنفس نمط تطبيقَي SMS وHIS (HttpURLConnection + org.json + SharedPreferences + ViewModel واحد، واجهة عربية RTL).

- تسجيل الدخول (مع إعداد عنوان الخادم) وتغيير كلمة المرور الإجباري.
- خريطة الطاولات بالألوان مع تنبيهات: 🔔 نداء الزبون، ✅ صنف جاهز، 📱 طلب زبون (QR) بانتظار الموافقة. تتحدث تلقائيًا كل 5 ثوانٍ طالما التطبيق ظاهر، مع شريط "لا يوجد اتصال".
- شاشة الطاولة: الطلب الحالي، الموافقة على أصناف QR، "قدّمت" للأصناف الجاهزة، إلغاء بسبب، طلب الفاتورة/إعادة الفتح، نقل الطلب لطاولة فارغة، تلبية النداء.
- إضافة أصناف من المنيو (تصنيفات + بحث + إضافات) إلى سلة فيها كمية وملاحظة للمطبخ وعدد الضيوف، ثم إرسال واحد للمطبخ.
- الأدوار المسموحة: كابتن، كاشير، مدير، مالك (المطبخ يستخدم شاشة الويب).

الفتح والتشغيل: افتح مجلد `android/` في Android Studio (أو `gradle :app:assembleDebug` مع تثبيت Android SDK). على المحاكي يكون عنوان الخادم الافتراضي `http://10.0.2.2:4000`؛ وعلى جهاز حقيقي أدخل عنوان IP لجهاز الخادم من "إعدادات الخادم" في شاشة الدخول.

> **حالة التحقق:** طبقة البيانات (`data/`) مختبرة فعليًا على الخادم الحقيقي عبر `android/datalayer-test` (بدون Android SDK):
> `cd backend && npm run seed && npm run dev` ثم `cd android/datalayer-test && gradle run` (أعد `npm run seed` قبل كل تشغيل).
> أما واجهة Compose (`ui/`) فكُتبت ودُقّقت يدويًا لكنها **لم تُجمَّع ولم تُشغَّل بعد** لعدم توفر Android SDK في بيئة التطوير؛ توقّع أن تحتاج تعديلات طفيفة عند أول بناء في Android Studio.
